# Beam Weaver v0.4.1

This release clarifies some of the information that appears in the different options on the menu, to better assist users, in particular those using Beam Weaver for the first time.

## Menu guidance

- Each menu operation now explains its inputs, computation and saved outputs.
- Generation names the **fixed incident photon energies** sampled by Beam Spinner. It lists all 64 logarithmically spaced training values from 1 keV to 10 MeV, the five extra points near pair threshold (1.023, 1.030, 1.050, 1.075, 1.100 MeV), 63 validation midpoints and the nine test values (0.010, 0.020, 0.050, 0.100, 0.5, 1, 2, 5, 10 MeV). It shows progress within each split and explains where the 69 × 9 + 21 = 642 training, 63 × 9 + 16 = 583 validation and 9 × 9 + 3 = 84 test reference sampling sets come from.  
- Training explains that 13 heads are fitted separately, with up to 400 epochs or grouped empirical distributions and 20 for the four pair-direction heads fitted to individual events. Validation cross-entropy chooses the best checkpoint and supports early stopping. Single-head training in a fresh run leaves the other heads untrained; resume a matching complete policy to replace one head.
- Comparison calls its input **primary photon histories per selected energy per method**. The default 2,000 is applied separately to MC1, MC2 and Beam Weaver at each of the four default comparison energies.
- Automatic output names now follow `runs/<command>-YYYYMMDD-vN`, with the next unused `vN` for that operation on that UTC date.  Explicit output paths and training resume paths remain explicit. Command audit records within a run use `command-YYYYMMDD-vN.json`; dataset and checkpoint names are unchanged.


## Scope and citation

Beam Weaver is a research prototype for photon transport in water. Photon free-flight sampling and approximate electron/positron transport remain conventional Monte Carlo components. Passing software regression checks does not establish physical or clinical validation.
